# Deployment — hanguk.dev/geoguess

The human-vs-model webapp is deployed at [hanguk.dev/geoguess](https://hanguk.dev/geoguess/). This document covers how the deployment runs, how to push an updated model to it, and why the live site currently serves predictions from an older checkpoint than the one committed to this repo.

## Stack

- **Host.** Ubuntu 22.04 VPS (RackNerd), reachable as `hanguk.dev`.
- **Web server.** Apache 2 (`/etc/apache2/sites-enabled/hanguk.dev-le-ssl.conf`), proxying `/geoguess/` to Gunicorn on port 5000.
- **App runtime.** `gunicorn` managed by systemd as the `geoguess` service.
- **SSL.** Cloudflare origin certificate (valid through 2039).
- **Storage.** SQLite database at `~/geoguess/webapp/data/guesses.db` (human guesses), plus the extracted images at `~/geoguess/webapp/data/images/`.

The Flask app itself is what lives in this repo at `webapp/app.py`. On startup it reads `data/original1000.zip` and `data/experiment_data.json`, extracts images into `webapp/data/images/`, and generates `webapp/data/manifest.json`. The manifest is what drives which prediction the user sees marked as "the model's guess" after each round.

## Environment

The service expects one env var:

```
GEOGUESS_EXPORT_KEY=<opaque-secret>
```

This gates the `/api/export` endpoint, which returns the full human-guess table as JSON. If the variable is unset, the endpoint returns 403 to all callers. Set it in the systemd unit (`/etc/systemd/system/geoguess.service`) via `Environment=` and reload the unit with `systemctl daemon-reload && systemctl restart geoguess`.

Export is then reachable at:

```
https://hanguk.dev/geoguess/api/export?key=<your-secret>
```

See `.env.example` for the full list of variables the project uses.

## Updating the Deployment

From a laptop that has the updated files:

```bash
# Copy the webapp source + any refreshed data bundle
scp webapp/app.py hanguk:~/geoguess/webapp/app.py
scp webapp/templates/index.html hanguk:~/geoguess/webapp/templates/index.html
scp data/experiment_data.json hanguk:~/geoguess/data/experiment_data.json

# Restart
ssh hanguk 'sudo systemctl restart geoguess && systemctl status geoguess --no-pager'
```

Reloading `experiment_data.json` is what changes the served model predictions. The webapp re-generates `webapp/data/manifest.json` on startup only when it's missing, so after an update you also need to delete the stale manifest so it rebuilds:

```bash
ssh hanguk 'rm -f ~/geoguess/webapp/data/manifest.json && sudo systemctl restart geoguess'
```

## Deployed vs. Committed Checkpoint

The live site currently serves predictions generated by the **older** checkpoint committed as `data/best_model.pt` (32.1% accuracy on the 1,000-image benchmark). The newer checkpoint committed as `data/best_model_efficientnet_b0.pt` (64.7% accuracy) is what's analyzed end-to-end in the notebook and reported in the README.

This divergence exists by design: the 2,579 human guesses in the case study were collected while the older model was live, so the paired McNemar's comparisons have to be scored against that same checkpoint. Swapping the live model mid-study would have invalidated the paired comparisons, so the decision was to freeze the live predictions until data collection ended.

**To bring the live site in line with the committed model** (recommended once data collection is fully closed):

1. Regenerate `data/experiment_data.json` in the notebook by re-running the `evaluate` mode against `data/best_model_efficientnet_b0.pt` (see `README.md` for the run mode table).
2. `scp` the refreshed `experiment_data.json` to the server.
3. Delete `webapp/data/manifest.json` on the server and restart the service (commands above).
4. Update `MODEL_CARD.md`'s "Deployed vs. committed" section so future readers know the live site and the repo are back in sync.

Any new human guesses collected after the swap should be stored under a new experiment label so old and new comparisons aren't silently mixed.

## Health Checks

- **Site is up.** `curl -sI https://hanguk.dev/geoguess/ | head -1` should print `HTTP/2 200`.
- **Service is running.** `ssh hanguk 'systemctl status geoguess --no-pager'` — expect `active (running)`.
- **Guesses are writing.** `ssh hanguk 'sqlite3 ~/geoguess/webapp/data/guesses.db "SELECT COUNT(*) FROM guesses;"'`.
- **Export still works.** `curl -s "https://hanguk.dev/geoguess/api/export?key=$GEOGUESS_EXPORT_KEY" | head -c 200`.
